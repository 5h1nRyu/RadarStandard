# 架构与扩展

数据流是「作品加载与校验 → 单一绝对时间轴 → 组件绑定 → 主题化绘制」。编辑器修改布局配置，演示和 VideoMaker 使用相同的组件渲染器。

## 模块边界

- `model/types.ts` 是格式和协议的类型定义；`schema.ts` 在导入边界校验真正的外部 JSON，不只依赖 TypeScript。
- `model/timeline.ts` 从绝对毫秒定位当前记录、局部时间、进度和插值。不累加四舍五入的帧间隔，跳转记录、实时轮播和离线渲染共享这些函数。
- `assets/project.ts` 提供本地文件夹和发布 URL 两种来源，组件只使用统一的 AssetSource；本地对象 URL 在更换作品和释放时撤销。图片预加载不写回布局。
- `app/application.ts` 管理作品、布局、选中、播放和生命周期；`Stage` 管理画布等比缩放、组件实例和主题背景。绘制串行排队，避免异步背景重叠。
- `components/view.ts` 仅依据绑定和当前记录更新内容。`radar.ts` 按逻辑尺寸绘图，内部位图乘实际像素比例。
- `editor/` 提供操作区与指针坐标换算；`export/` 负责协议调度，不另做一套动画实现。

## 添加组件类型

1. 在 `ComponentType` 增加类型。
2. 在 `COMPONENTS` 声明名称、默认尺寸、兼容字段类型和默认字段。
3. 在 `ComponentView` 中创建 DOM 并实现当前帧更新；不要按全局 ID 或组件列表的固定下标寻找数据。
4. 如需新绑定类型或格式，在 schema 和绑定控件中同时添加校验和编辑支持。
5. 在主题 CSS 中定义默认视觉参数，在 animate 中定义当前帧的入场效果。
6. 检查多个实例是否相互独立，并验证布局保存和重新导入。

## 生命周期

普通打开时先检查 `__VIDEO_EXPORT_REQUEST__`，仅在它不存在且有作品数据时启动 RAF。一次普通播放帧读取实际时间差、计算时间轴、等待 Stage 绘制完成，再请求下一帧。暂停停止调度。

导出接口在启动时即可发现；getManifest 等待作品加载，不启动动画；prepare 校验参数、配置 DPR、准备主题资源；reset 重建背景、回到时间轴起点；renderFrame 串行接受全局帧号、绘制并等待依赖；dispose 停止播放并释放资源。只读取元数据后 dispose 也安全。

内置主题声明顺序模式。导出器导出中间片段时先预推进前置帧；第 0 帧仅展示初始状态。数值形变按绝对时间计算，背景也必须重置种子和内部历史。新增主题后应运行真实浏览器哈希检查。
